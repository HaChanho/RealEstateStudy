## 읽는 순서

1. **스펙 §1~§2** — 무엇을 위한 개편인가, 무엇이 확정 제약인가
2. **스펙 §3·§3A** — 개편 전 실측값. 모든 결정의 근거다
3. **스펙 §5~§7** — 결정과 그 이유
4. **스펙 §8** — **하지 않기로 한 것**과 그 이유 (다크모드·홈 색 통일·타임라인 전면 재설계 등)
5. **스펙 §11** — 검증 기준과 측정 전제

## 검증 실행

`verify-snippet.js` 를 브라우저 콘솔에 붙여넣고 **두 번 실행**한다.

```
1회차 → localStorage 를 비우고 자산 갱신 후 재로드
2회차 → 전이를 끄고 측정 + 판정
```

두 번 나눠 실행하는 이유는 스펙 §11.1 에 있다. 요약하면 **전이가 진행되지 않는 상태**나
**저장소에 남은 값**이 측정을 조용히 왜곡하며, 실제로 이 때문에 오진 2건과 라이브 회귀 1건이 났다.

## 문서 안의 경로 표기

계획 문서들은 작업 당시의 상위 디렉토리 기준 경로(`_workspace/_tests/` 등)를 일부 포함한다.
이 저장소 밖의 로컬 작업 공간이며, **저장소 안에서 찾을 수 없는 경로는 그 때문이다.**
저장소 기준으로는 `calendar/`·`timeline/`·`shared/` 만 유효하다.
