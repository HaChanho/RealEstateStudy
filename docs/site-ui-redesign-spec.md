## 1. 목표와 성공 기준

**한 문장 기준:** *"이 도구를 처음 여는 지인이 60초 안에 '이번 달에 갈 만한 기일'을 지목할 수 있는가."*

라운드 전체가 이 문장에 걸린다. 개선안이 서른 개 나와도 이 문장에 답하지 않으면 자른다.

**부차 기준 2개:**
- 매일 쓰는 소유자의 스캔·필터·비교 속도가 지금보다 느려지지 않을 것
- **모델이 얼마나 맞았는지를 두 페이지가 같은 축으로 말할 것** — 캘린더 성적표(§7.4 매각가율 예측 오차)와 타임라인(§7.5 R1 계획 vs 실제)이 같은 질문에 답한다. 현재는 캘린더가 틀린 지표(FP=0)를 광고하고 타임라인은 예측 데이터를 아예 안 읽는다

### 3.4 캘린더 — 확인된 결함 7가지

| # | 결함 | 위치 / 근거 |
|---|---|---|
| B1 | **칩이 2줄로 깨짐** | `.chip`은 `grid-template-columns: 22px 1fr auto`(3열)인데 자식이 `rating`+`text`+`trail`+`mini` 4개. `trail`이 붙으면 `mini`가 2행으로 밀림. v0.5.0 주석이 이 문제를 진단하고 `chip-trail`을 도입했으나 `mini`가 4번째 자식으로 남아 미해결 |
| B2 | **유령 D-Day 배지** | `renderCalendar`가 `dCls`를 `dateRow`에 붙일 때 `cases.length`를 보지 않음. 사건 0개 칸에도 pulse 애니메이션 배지가 렌더 |
| B3 | **딥링크가 달을 안 옮김** | `applyUrl`이 `state.selectedId`만 설정하고 `state.currentMonth`는 미변경. `?case=`로 7월 사건을 열면 그리드는 8월(빈 화면) |
| B4 | **칸 내부 정렬 없음** | `byDate.get(c.saleDate).push(c)` — `getFiltered()` 순회 = cases.js 배열 삽입 순서. `+N건`으로 잘리는 게 최고 물건일 수 있음 |
| B5 | **홈이 막다른 길** | `site-nav.js`가 `calendar/`·`timeline/`에만 로드. GitHub Pages 루트(지도)에 캘린더 링크 없음. 또한 `site-nav.js`가 `</body>` 직전에 로드돼 body 상단 주입 → 레이아웃 점프 |
| B6 | **성적표 FP가 구조적으로 0** | quadrant 정의가 `verdict GO/NO-GO × sold/failed`인데 매각 41 : 유찰 5 시장에서 "GO 했는데 유찰"은 거의 불가능. `GO 적중률 100%`는 실력이 아니라 정의의 부산물. 69건 중 36건은 quadrant 자체가 null |
| B7 | **stale 경고 없음** | 데이터가 49일 지났는데 화면 어디에도 표시 없음 |

### 3.5 미검증 (기록만)

- 상세 패널을 480px로 줄였을 때 가로 오버플로 발생 여부 — 측정 시 패널이 3px로만 열려 재현 실패. 구현 중 재측정한다.
- `@media (max-width: 900px)`가 **뷰포트 폭**에 걸려 있어, 좁은 패널 안의 2컬럼 레이아웃이 1컬럼으로 복귀하지 않을 가능성. 컨테이너 쿼리 전환이 필요할 수 있음.

### 3A.1 프라이버시 구조 (확인됨 — 변경 대상 아님)

```
repo 공개 여부 : PUBLIC
holdings.enc.json : origin/main에 추적 중 — 의도적·문서화된 정책
암호 : AES-GCM-256 + PBKDF2-SHA256 600,000회
비밀번호 : encrypt.mjs가 CSPRNG 160비트 생성. 사용자 자유입력 불가
```

## 4. Phase 0 — 도달 가능성 (재설계 착수 전)

**이 단계가 먼저인 이유:** §3.1대로 오늘 링크를 열면 빈 화면이다. 채도 예산·레일 폭·밀도는 전부 "칩이 화면에 있을 때"의 문제다. 순서를 지키지 않으면 아무도 도달하지 못하는 화면을 고치게 된다.

또한 B1(칩 2줄)을 고쳐야 5월 그리드의 **진짜 높이**를 알 수 있고, 그래야 레일·셀 폭을 계산할 수 있다.

| # | 작업 | 해결 |
|---|---|---|
| P0-1 | 진입 월 = **데이터가 있는 가장 가까운 달** (미래 우선, 없으면 최근 과거) | §3.1 |
| P0-2 | `applyUrl`이 `case`의 `saleDate`로 `currentMonth` 설정 | B3 |
| P0-3 | D-Day 배지를 `cases.length > 0`일 때만 렌더 | B2 |
| P0-4 | 빈 상태 컴포넌트 — "이 달에는 사건이 없습니다 · 5~7월에 76건" + 이동 링크 | §3.1 |
| P0-5 | stale 배지 — `갱신 N일 전`, 30일 초과 시 경고 톤 | B7 |
| P0-6 | 홈에 캘린더·타임라인 링크 + `site-nav.js`를 `<head>`로 이동 | B5 |
| P0-7 | 칩 자식 4개 → 3개 (`mini`를 `trail`에 병합) | B1 |
| P0-8 | 칸 내부 **별점 내림차순** 정렬 | B4 |
| P0-9 | 타임라인 `today()` **UTC → KST** 수정 | T4 |
| P0-10 | 타임라인 375px 가로 오버플로 수정 | T5 |

**Phase 0 완료 후 재측정하고, 그 값으로 Phase 2의 폭 계산을 확정한다.**

### 5.2 채도 예산 — 원천 2개

현재 채도 원천이 15개(verdict 6 + 별점 5 + D-Day 3 + 가격 + 결과)라 눈이 우선순위를 잡지 못한다.

**규칙: 채도는 "행동을 바꾸는 정보"에만.**

| 순위 | 정보 | 처리 |
|---|---|---|
| 1 | **별점** (우선순위) | 유일한 풀채도. 칩 좌측 원 |
| 2 | **손실 신호** (마이너스 마진) | 적색, 예외적으로만 |
| — | verdict · 가격 · 법원 · 면적 | 무채색 + 굵기·크기로 구분 |
| — | **D-Day** | **채도 제외.** 오늘 열 강조 + 이번 주 배경 밴드로 대체 |

**D-Day를 뺀 근거:** 달력의 x·y 좌표가 이미 시간 축이다. 색은 중복 인코딩이고, 실제로 이 중복이 B2(유령 배지 — 화면에서 채도가 가장 높은 요소가 아무것도 가리키지 않음)를 낳았다.

### 5.3 타이포 · 아이콘

- **하드코딩 hex 전부 제거** → 토큰화. 현재 `#ef4444`·`#f59e0b`·`#0284c7`·`#65a30d`·`rgba(...)` 등 수십 개가 흩어져 있다. 다크모드 채택 여부와 무관하게 필요한 작업이며, 나중에 다크를 켤 때 팔레트 한 벌 추가로 끝나게 만든다.
- **숫자**: `tabular-nums` 전면 적용 — 가격 세로 비교가 이 도구의 핵심 동작
- **아이콘**: 이모지 20종 → 인라인 SVG ~12종. 이유는 렌더 실패가 아니라 ①11px에서 판독 불가(`🏁`·`📅`) ②플랫폼마다 그림이 달라 통제 불가 ③토큰 색 적용 불가. `★`(U+2605)는 텍스트 기호이므로 유지
- **웹폰트**: **Phase 0 이후로 연기**. 폰트가 가장 아픈 자리가 11px 칩인데 지금 칩이 2줄로 깨져 있어 효과를 측정할 수 없다. 도입 시 CDN이 아니라 **subset 셀프호스팅**(정적 사이트라 같은 오리진, 외부 장애에 영향 없음). 현재 `font-family`의 `Pretendard`는 `-apple-system`이 앞서 macOS에서 한 번도 사용되지 않는다

### 6.2 폭 배분 — Phase 0 재측정 후 확정

그리드가 **4열**(3열 아님)이므로 셀 폭 여유가 §3 이전 가정보다 좁다. 칩 내부 고정 소비분(셀 패딩 + 칩 패딩 + 별점 원 22px + 갭 + 가격)을 빼면 단지명에 남는 폭이 결정된다. 단지명 중앙값은 8자다.

**결정 규칙:** 1280px에서 `레일 + 그리드(4열) + 패널`을 배치했을 때 **셀당 단지명 표시폭이 한글 7자 미만이면** 다음 중 하나를 택한다.

- (A) 레일을 **≤1440px에서 기본 접힘**(아이콘 모드)
- (B) 레일을 버리고 상단바로 흡수
- (C) 상세 패널을 **≤1440px에서 오버레이**로

레일에 들어갈 컨트롤이 12개(판정 토글 6 + 셀렉트 5 + 검색)로 아이콘화가 어렵다는 점에서 **(C)가 유력**하나, Phase 0 재측정 전에는 확정하지 않는다.

**§6.2 확정 (2026-08-26) — (D) 아이콘 레일 64px + 패널 clamp**

**정정된 공식** (실측 대조로 소수점까지 일치 검증):
```
col = (innerWidth − rail − panelOccupied − 15(스크롤바) − 40(wrap padding) − 12(컬럼갭×3)) / 4
      panelOccupied = 나란히 ? panelW + 12(margin-left) : 0
합격선: col ≥ 216  = 60(고정) + 65(단지명 6자+…) + 91(마진바 제거 후 trail p90)
```
칩 고정소비는 58이 아니라 **60**이다 — `.chip`에 `border:1px solid transparent`가 있어 판정별 클래스가 `border-color`만 덮으므로 테두리 2px이 항상 존재한다.

**병목은 레이아웃이 아니라 칩이다.** 실측:
- 칩 라벨 = `사건번호 + 단지명`이고 **사건번호가 라벨의 50%**(p50 65.1px / 130.4px)
- `shortenComplex`가 7자 하드컷 → 단지명 폭이 **p50 72.7 ≈ p90 75.5 ≈ max 75.5로 포화**
- → **하드컷을 풀지 않으면 레이아웃으로 확보한 폭이 한 픽셀도 쓰이지 않는다.** 칩 재설계가 레이아웃보다 선행한다.
- 단지명 6자와 8자의 변별력이 동일(같은 날 중복 5/76). 전체 이름만 2/76로 개선.

**배치**

| 조건 | 레일 | 그리드 | 패널 | col |

| ≥1400px | 64 상주 | 4열 | **나란히** `clamp(380px, 100vw−1020px, 480px)` | 219→324 |
| 992–1399px | 64 상주 | 4열 **전폭** | **오버레이** `min(480px,46vw)` + backdrop, Esc/외부클릭 닫기 | 215→309 |

### 6.3 그리드

- 각 주가 독립 행. **행 높이 = 그 주 최다 사건 수**에 맞춰 가변 (`min-height: 120px` 고정 제거)
- 사건 없는 주 → **32px 요약 행** (`5/4 – 5/10 · 사건 없음`). 완전 제거하지 않는 이유는 날짜 감각 유지
- 날짜 헤더에 **카운트 배지** (`19 · 8건`) — 접힌 상태에서도 밀도 인지
- 기본 노출 **6개** + 단순 `+N건`. 별점 내림차순 정렬(P0-8) 전제
  - *별점 분포 라벨(`+8건 (★5 1 · ★4 2)`)은 폐기* — ★5가 전체 0개라 `(★5 0)` 같은 노이즈가 된다
- **칸 클릭 시 그날 전체를 상세 패널에 리스트로.** 현재 칸 빈 공간에 핸들러가 없다. "그날 훑기"는 달력의 자연스러운 동작이며, 밀도 높은 날 대응도 겸한다

### 6.4 반응형

| 폭 | 레일 | 그리드 | 상세 |
|---|---|---|---|
| ≥1440px | 고정 | 4열 | 나란히 |
| 768~1439px | §6.2 결정에 따름 | 4열 | 오버레이 |
| <768px | 드로어 | **아젠다 리스트** | 바텀시트 |

**모바일이 그리드를 버리는 근거:** 375px에서 4열은 칸 폭 ~80px이라 단지명이 들어갈 수 없다. 현재 첫 화면 노출 사건 0건(크롬이 47%).

## 7. Phase 3 — 컴포넌트

### 7.1 칩

- **단지명이 첫 줄.** 사건번호는 상세에서만 (11px에 `2024·112185 배방…`은 판독 불가)
- **가격을 칩 안 우측**에 `tabular-nums`. 현재는 칩 밖 둘째 줄이라 세로 비교 불가
- **자식 3개 유지** (grid 3열과 일치) — B1 재발 방지
- verdict는 **무채색 점 + 텍스트** (단, §10 미결)
- 종료·변경 건은 **취소선 대신 45% 투명** (취소선은 글자를 더 못 읽게 만든다)

### 7.2 상세 패널

- **카드 중첩 3단 → 구분선 1단.** 현재 `카드 > 카드 > 회색상자`
- **요약 스트립**: 감정가 · 최저가(%) · KB시세 · 미시마진 4칸
- **빈 값은 행 자체를 삭제.** 현재 `낙찰가 —/낙찰가율 —/응찰자수 —/실제매각일 —` 4줄 ~200px → `결과 미확인 (변경·취하 추정)` 한 줄
- `openDetail`이 **722줄**(전체 JS의 40%)로 헤더·시세·회고·권리·수치·링크를 모두 그린다. **섹션별 함수로 분할**한다

### 7.3 리스트 뷰

행 높이 **210px → 44px**, sticky 헤더. 47건이 한 화면에 들어오게 한다.

### 7.4 성적표 뷰 — 지표 교체

**2×2 혼동행렬을 만들지 않는다.** B6대로 FP가 구조적으로 0이라 `GO 적중률 100%`는 틀린 자신감이고, 표본의 절반(36/69)이 quadrant null이다.

**대체 지표 — 매각가율 예측 오차:**

```
predictedSaleRate와 soldRate가 둘 다 있는 19건
  평균 오차   −0.6%p   (거의 무편향)
  절대오차    5.6%p
  범위        −11.7%p ~ +20.3%p
```

읽히는 문장: *"모델이 예측한 매각가율 vs 실제 낙찰가율 — 19건 평균 0.6%p 낮게 봤고, 보통 ±5.6%p 안에 들어옵니다."* ML 용어가 없고, **입찰가를 얼마나 믿을지**를 직접 말한다.

- 이번 범위는 **숫자 3개 + 표본 수 병기**. 산점도는 축·툴팁을 직접 짜야 하므로 다음 차수
- `FN 11건`은 **"걸렀는데 실제로 좋았던 물건"** 리스트로 별도 유지 — 배울 게 있는 목록
- `NO-GO 정확도 21%`("거른 것 중 79%가 팔렸다")는 아픈 진실이므로 **지우지 않고** 문장으로 풀어 유지
- **results.js 고아 32건**을 화면에 표시한다. 현재 조용히 누락되어 표본을 왜곡한다

### 7.5 타임라인 — 부분 수리 (재설계 아님)

194줄에 재설계를 붓지 않는다. 물건이 1건이고 토큰 충돌이 0건이다. 대신 **`render()` 3곳 + CSS 4줄**을 고친다. 반나절 규모.

## 10. 미결 사항

**verdict를 무채색으로 강등할 것인가.**

데이터상 양방향이 다르다:

```
fail      → ★1 19건, 무등급 10건        (★1 외 예외 0건 → 별점과 완전 중복)
expired   → 전부 무등급
candidate → ★1 5 · ★2 5 · ★3 5 · ★4 4 · 무등급 4   (평평 → 별점과 직교)
hold      → ★1 1 · ★2 3 · ★3 4 · ★4 2
pass      → ★4 1 · 무등급 1
```

음의 방향(fail·expired)에서 verdict를 죽이는 것은 정보 손실이 아니라 **중복 제거**다. 그러나 양의 방향에서는 직교하며 **`★1 candidate`가 5건 실재**한다. verdict를 무채색 점으로 강등하면 candidate/hold 구분이 약해지는데, 그것이 정확히 "그날 법원에 갈까"를 결정하는 구분이다.

대안(verdict × 별점을 **행동축 3단계**로 통합)은 경계 규칙을 새로 정의·유지해야 하는 리스크가 있고, `EP70`이 29/76(38%)에만 있어 커버리지도 낮다.

**결정 (2026-08-26, 확정):** 하이브리드. **채도가 아니라 점의 형태로 구분한다.**

```
fail · expired  →  점 없음 + 45% 투명      (★1/무등급과 100% 중복 → 강등)
candidate       →  ● 채움                  (직교 → 형태로 보존)
hold            →  ◐ 반채움
pass            →  ○ 외곽선
pending         →  ◌ 점선
```

음의 방향은 중복이므로 지우고, 양의 방향은 직교하므로 보존하되 **채도 예산을 쓰지 않는 축(형태)으로 옮긴다.** 이로써 `★1 candidate`(5건 실재)와 `★1 hold`가 무채색 안에서도 구별된다.

**검증:** §11.2 #10(색 회상 테스트)에 "점 모양이 뭘 뜻했나"를 추가한다. 3명 중 2명이 못 맞히면 형태 구분이 실패한 것이므로 verdict를 패널 텍스트로만 내린다.

## 11. 검증

### 11.1 자동 (커밋 전 실행)

현재값은 2026-08-26 실측.

#### 측정 전제 2가지 — 반드시 먼저 적용한다

이 둘을 빠뜨려서 **실제로 오진 2건과 라이브 회귀 1건이 발생했다.** 선택이 아니라 전제다.

**① 전이·애니메이션을 끈다**

브라우저 팬이 숨겨져 있으면 프레임을 합성하지 않아 **CSS 전이가 진행되지 않는다.**
`transition: width .25s` 가 걸린 요소를 재면 시작값에 머물러 있다.

> 실제 사고: 상세 패널이 `3px`(테두리만)로 측정돼 **"데스크톱에서 패널이 열린 적이 없다"고 오진**했다.
> 그 오진을 고치려 `flex-basis` 로 전환했고, 그게 **진짜 회귀**가 되어 배포까지 나갔다
> (`flex-basis` 에 명시적 길이를 주면 그 값이 주축 크기를 결정해 `width` 가 무시된다).

```js
// 모든 측정 스니펫 맨 앞에 넣는다
document.head.appendChild(Object.assign(document.createElement('style'), {
  textContent: '*{transition:none!important;animation:none!important}'
}));
void document.body.offsetWidth;   // 강제 리플로우
```

**② 저장 상태를 비우고 "새 방문자" 조건으로 잰다**

`localStorage` 에 남은 값이 CSS 경로를 우회한다.

> 실제 사고: 드래그 테스트로 남은 `calendar.panelWidth.v3` 가 인라인 `width` 를 설정해
> **CSS 기본값 경로를 건너뛰었다.** 로컬은 420px 로 통과했지만 저장값이 없는
> 실제 방문자에게는 패널이 열리지 않았다. 라이브에서야 드러났다.

```js
try { localStorage.clear(); } catch (e) {}
location.replace(location.pathname + '?cb=' + Date.now());
```

**③ 스크린샷은 프로그램 스크롤을 반영하지 않는다**

`window.scrollTo()` 후 찍으면 **스크롤 전 프레임**이 나온다(①과 같은 계열의 팬 한계).

> 실제 사고: 타임라인 하단을 찍으려다 "상단이 텅 빈 화면"을 보고 **레이아웃 버그로 오인**했다.
> DOM 은 `scrollY 900`, 모든 섹션 `visible`·`opacity 1`, 위치가 118→1,920px 로 연속인 정상 상태였다.

```js
// 대상보다 위에 있는 형제를 일시적으로 숨겨 뷰포트 최상단으로 끌어올린다
peekBelowFold('#detail', '.fold');   // #detail 의 자식 중 .fold 만 남김
// ... 스크린샷 ...
peekBelowFold.restore();
```
`docs/verify-snippet.js` 에 헬퍼로 들어 있다.

**④ 보조 규칙**

- 캐시: 정적 자산은 `fetch(url, {cache:'reload'})` 로 먼저 갱신한 뒤 `location.replace('?cb='+Date.now())`.
  HTML 만 캐시버스트하면 `shared/*.js`·`theme.css` 는 구버전이 남는다.
- **측정은 조작과 다른 tool call 에서** 한다. 같은 호출 안에서 클릭 직후 재면 레이아웃이 확정되기 전 값을 읽는다.
- 뷰포트 에뮬레이션은 **레이아웃 폭에 반영되지 않을 수 있다**(`window.innerWidth` 가 고정). 좁은 폭 검증은
  뷰포트 대신 **컨테이너를 CSS 로 직접 좁혀서** 메커니즘을 확인한다.
- 스크린샷과 수치 측정을 **교차 검증**한다. 둘이 어긋나면 측정 쪽을 의심한다.
- **플래그를 URL 쿼리에 두지 않는다.** 앱의 `syncUrl()` 이 `URLSearchParams()` 를 새로 만들어
  `view`/`case` 만 남기고 나머지를 지운다. 실행 상태 플래그는 `sessionStorage` 에 둔다.
- **숨은 요소는 `innerText` 로 못 읽는다.** 성적표는 기본 닫힘인 플라이아웃 안에 있어
  `document.body.innerText` 에 잡히지 않는다. 존재 확인은 `textContent` 로 한다.
